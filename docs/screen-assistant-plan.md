# 屏幕助手:数枢的增量演进方案

> 状态:方案已定稿(2026-09),按三阶段递进实施,详见 `docs/desktop-implementation-plan.md`(实施计划)。
> 目标:从"上传文件的离线分析 Agent"演进为"实时屏幕理解助手"(用户语音+屏幕演示,Agent 实时分析),同时**保持原有上传文件对话分析功能零退化**。
> 配套:`docs/agent-technical-guide.md`(现状结构)、`docs/DESIGN.md`(设计决策)。

## 1. 背景与定位

**现状(离线版)**:用户上传数据文件(csv/json/sqlite/doc/briefing.mp4),打字提出分析目标,Agent 全自动执行并返回结果。视频链的价值是"任务讲解视频中的口径与答案"。

**局限**:离线视频形态除评测/竞赛场景外缺乏现实场景;真实需求更接近"用户边说边指,Agent 看屏幕分析"。

**目标形态(在线版)**:用户共享屏幕(面板/表格/PPT),语音说"帮我对比这个季度和上个季度的销售额",Agent 实时看屏幕、听指令、复用现有分析引擎,在**屏幕悬浮卡片**中给出结论(表格/图表可展开)。

**核心原则:增量演进,不替代**——分析引擎、上传链路、聊天界面全部保留;屏幕助手是新的输入形态与交互形态。

## 2. 总体架构

```mermaid
flowchart TB
    subgraph 采集层[采集层(桌面壳)]
        SC[ScreenCaptureKit<br/>屏幕帧流 5-10fps]
        MC[麦克风流 16kHz]
    end
    subgraph 感知层[感知层(复用视频链资产)]
        FD[关键帧采样<br/>画面变化检测]
        ASR[whisper 流式转写<br/>word 级时间戳]
        LAYOUT[hiccup 版面树<br/>面板/表格结构]
    end
    subgraph 记忆层
        CTX[会话上下文<br/>关键帧快照 + 转写 + 分析结论]
    end
    subgraph Agent层[Agent 层(复用现有管线)]
        ROUTE[意图路由<br/>闲聊/指令/分析]
        PLAN[规划器]
        SOLVE[求解器<br/>工具: 查库/计算/画图]
    end
    subgraph 交互层
        VUI[语音/文字回复]
        OVL[屏幕悬浮卡片<br/>结果呈现]
    end
    SC --> FD --> CTX
    MC --> ASR --> CTX
    SC --> LAYOUT --> CTX
    CTX --> ROUTE --> PLAN --> SOLVE
    SOLVE --> VUI
    SOLVE --> OVL
```

**与现状的关系**:采集层→感知层→记忆层是新增长链路;Agent 层与交互层基本复用。相当于在"上传文件"之前增加一条"屏幕感知"的数据生产路径。

## 3. 分层技术方案

### 3.1 采集层

| 项 | 选型 | 说明 |
|---|---|---|
| 屏幕采集 | macOS **ScreenCaptureKit**(Swift 侧车);Windows DXGI 桌面复制 | 系统级 API,窗口级采集,权限受系统管理 |
| 音频采集 | 系统麦克风 16kHz 单声道 | 配合 local VAD 切句 |
| 桌面壳 | Tauri(React 前端零改造复用)+ Python 侧车 | 即此前评估的 macOS 桌面方案;屏幕权限需 Tauri 侧车桥接 |

### 3.2 感知层(全部复用现有视频链资产)

| 组件 | 现状 | 屏幕助手改造 |
|---|---|---|
| 关键帧采样 | 码率突变检测幻灯片(文件) | 改帧间差分/直方图对比(流);静止降采样率省 token |
| ASR | faster-whisper medium(**已下载离线模型**) | 加 local VAD 切句 → 增量转写;word 级时间戳保留 |
| 版面树 | hiccup(面板/表格 DOM 结构) | 直接复用,输入改实时截图 |
| 时间轴交错 | 帧+旁白按时间戳交错 | 复用算法,帧源改实时流 |
| 多模态理解 | `VIDEO_MODEL_*`(qwen-vl-max 已配置) | 零改动 |

### 3.3 记忆层(会话上下文)

- 只存**变化关键帧 + 转写文本 + 分析结论**,旧帧降采样
- 与 checkpoint"每轮事实源"思想一致;实时会话是"长 thread 持续追加",需与会话模式区分(见 §5 隔离设计)

### 3.4 Agent 层(复用现有管线)

- **意图路由**:语音转写文本 = 新的分析目标 → clarify 三态判定(闲聊/澄清/直通)完全复用
- **规划/求解/解读**:零改动;规划三 Agent 对屏幕抽取的临时数据同样适用
- **工具扩展(二期)**:截图指定区域、点击/输入控制等"操作屏幕"工具,供 Agent 主动获取更多信息

### 3.5 交互层

- 结果悬浮卡片(Overlay 窗口,不遮挡屏幕):短摘要 + 可展开表格/图表
- 语音合成(TTS)可选;打字聊天界面保留,作为同一会话的并行通道

## 4. 复用映射(现有资产 → 屏幕助手)

| 现有组件 | 屏幕助手角色 | 改动量 |
|---|---|---|
| 视频链(抽帧/ASR/hiccup/交错) | 感知层核心 | 输入改流,算法不动 |
| whisper 离线模型 | 流式转写 | 加 VAD |
| `VIDEO_MODEL_*` 视觉模型 | 多模态理解 | 零改动 |
| clarify 三态 + interrupt/resume | 语音指令路由与打断 | 零改动 |
| 规划三 Agent / 求解 ReAct / 图表 | 分析与结果 | 基本复用 |
| 上传/数据源注册 | 屏幕抽取临时数据入库 | 新增一条生产路径 |

## 5. 与现有功能的隔离设计(保证零退化)

1. **数据集抽象不动**:管线认"注册进 DuckDB 的数据源 + context 描述",不关心数据来自上传还是屏幕抽取
2. **新增独立端点**:流式会话走新端点(如 `/live/sessions/{id}/events`),现有 `/sessions/{id}/chat` 一行不改
3. **会话模式区分**:checkpoint 增加 `mode: chat | live` 字段;live 模式为长 thread 持续追加,chat 模式保持"每轮独立分析"语义
4. **独立桌面壳**:屏幕助手是另一个前端(桌面 App)复用同一后端 API;网页版不受任何影响
5. **资源错峰**:本地 whisper 转写为 CPU 密集,与视频预处理错开或加队列(部署问题,非功能问题)

## 6. 关键难点与对策

| 难点 | 对策 |
|---|---|
| 延迟链(语音→理解→分析→回复 <3s) | VAD 边听边转写;意图判定轻量;结果先短摘要后详情 |
| 权限与隐私 | 转写/截图本地优先,必要时才上云模型;权限最小化提示 |
| 上下文爆炸 | 只存变化关键帧+转写+结论,旧帧降采样 |
| "这个"指代(说词与帧对齐) | word 级时间戳+帧时间戳交错(现有算法);hover/点击事件作锚点 |
| 分析中被打断 | interrupt/resume 天然支持;加取消路由 |

## 7. 分阶段路线

| 阶段 | 内容 | 周期 | 价值 |
|---|---|---|---|
| **M1 桌面化** | Tauri 壳 + Python sidecar 打包,双击即用(上传分析) | 1-2 周 | 验证 sidecar/权限/数据目录基础设施 |
| **M2 半实时** | 手动截图 + 语音(PTT)→ Agent 分析,悬浮卡 UI | 2-4 周 | 验证交互模型与产品价值 |
| **M3 实时闭环** | ScreenCaptureKit 帧流 + 流式 ASR + 实时循环 | 1-2 月 | 完整产品 |

## 8. 用户旅程(M3 完成后的交付形态)

**交付物**:DataPivot.app——原生壳(Tauri 窗口+菜单栏)+ Python 分析引擎(sidecar)+ 屏幕/语音采集组件 + whisper 本地转写 + 可选本地模型(ollama 内置)。模型支持**云 API 与本地模型双模式**,App 内一键切换/部署。

```
双击 App → 菜单栏图标 + 主窗口出现(即用,无终端)
    │
首次使用 → 设置页:选择「云 API」填 key,或「本地模型」一键下载(ollama)
    │
点击「开始屏幕共享」→ macOS 弹屏幕录制/麦克风权限 → 授权
    │
┌─────────────────────────────────────────────┐
│  边操作边说话:按住 ⌥+空格 说指令(PTT)        │
│  "对比这个季度和上个季度的销售额"             │
└─────────────────────────────────────────────┘
    │
Agent 实时:听指令 → 看当前屏幕(关键帧+版面树)
  → 查本地数据/计算 → 屏幕角落「悬浮卡片」:
  "Q3 销售额 1,240 万,环比 +18%。【展开表格】【导出 CSV】"
    │
用户继续:追问"再按产品线拆一下" / 点卡片看图表 / 让它写报告
    │
随时「停止共享」;对话与结果同步进主窗口会话历史
```

**关键体验设计**:不打断工作流(悬浮卡片不抢占焦点);混合模式(上传文件打字分析 与 屏幕语音分析共用会话与数据);权限只申请一次;隐私默认本地(转写/截图/分析在本地服务完成,仅必要时上云)。

## 9. 结论

方向成立且与现有资产高度契合:感知层(看屏幕/听语音)、分析层(SQL 求解/规划)、交互层(澄清/结果卡片)几乎直接搬移,新增集中在**流式接入 + 实时编排 + 桌面壳**。风险在延迟与权限体验,不在算法可行性。实施按 M1→M2→M3 三阶段递进,详见 `docs/desktop-implementation-plan.md`。
